# Огненный Ветер — Мобильный Терминал Музыканта & Data Studio
**Техническое задание, системная спецификация и архитектурное руководство**
*Версия: 3.3.0 (Сентябрь 2026) — Архитектура автономного клиента, постоянного хранилища IndexedDB v12 и геометрического парсера DOCX/OpenSong/ChordPro*

---

## 1. Концепция и назначение системы

«Огненный Ветер» — полностью автономный комплекс для музыкантов, состоящий из двух ключевых компонентов:
1. **Клиентский сценический терминал (`index.html`):**
   - Каталог песен с аккордами и быстрым поиском;
   - Полноэкранный контрастный режим «Концерт» с педальным управлением и автоскроллом;
   - Встроенный плеер репетиционных фонограмм (`альбом`, `запись`, `запись2`...`запись9`, `минус`, `импро`);
   - PWA с оффлайн Service Worker и бинарным хранилищем аудио в `IndexedDB v12`.
2. **Инженерная панель Data Studio (`data/admin.html`):**
   - Оцифровка архивов песен из Microsoft Word (`.docx`) с немоноширинным шрифтом Times New Roman;
   - Математический модуль геометрического выравнивания аккордов (OffscreenCanvas + Dynamic Programming);
   - Интерактивный Drag-and-Drop визуальный редактор аккордов над слогами;
   - Конвертация и экспорт в ChordPro, OpenSong XML, канонический `data/songs.csv`, а также печать в PDF и DOCX.

## 3. Спецификация структур данных

### 3.1 Каталог песен (`data/songs.csv`)
Кодировка: **UTF-8**, разделитель полей: **`;`** (точка с запятой). Многострочные тексты экранируются кавычками (`"`).

| Поле | Тип | Обязат. | Описание | Пример |
|---|---|---|---|---|
| `id` | String(4) | **Да** | 4-значный уникальный идентификатор с ведущими нулями | `0482` |
| `number` | String | **Да** | Номер песни в сборнике | `482` |
| `title` | String | **Да** | Название песни | `Белый снег` |
| `alt_title` | String | Нет | Дополнительное / альтернативное название | `Сборник 21, №1` |
| `author` | String | Нет | Автор слов и музыки | `Огненный ветер` |
| `key` | String | Нет | Основная тональность (C, Am, F#m и т.д.) | `Am` |
| `capo` | String | Нет | Лад каподастра | `2` |
| `tempo` | String | Нет | Темп в BPM | `90` |
| `time_signature` | String | Нет | Музыкальный размер | `4/4` |
| `body_chordpro` | Text | **Да** | Текст с аккордами в формате ChordPro | `1. [Am]Белый снег [Dm]заметёт...` |
| `body_plain` | Text | Нет | Чистый текст без аккордов для быстрого поиска | `1. Белый снег заметёт...` |
| `notes` | Text | Нет | Заметки (общие или с ролевыми тэгами `[leader]`, `[drums]`) | `[leader] Вступление с припева` |
| `is_empty_body` | Boolean| **Да** | Флаг песни только с названием (`true`/`false`) | `false` |

> **Нормализация ID:** Парсер `CsvHelper.parse` автоматически дополняет числовые идентификаторы нулями до 4 знаков (`482` ➔ `0482`), гарантируя целостность связей с аудиозаписями.

### 3.2 Реестр аудиозаписей (`data/audio.csv`)
| Поле | Обязат. | Описание | Пример |
|---|---|---|---|
| `id` | Да | Уникальный ID записи | `aud-0482-альбом` |
| `song_id` | Да | Номер песни (4 цифры) | `0482` |
| `label` | Да | Название песни или дорожки | `Белый снег` |
| `type` | Да | Тип дорожки: `альбом`, `запись`, `запись2`...`запись9`, `минус`, `импро` | `запись2` |
| `path` | Да | Относительный путь к файлу | `music/0482_запись2_Белый снег.mp3` |
| `filename` | Да | Физическое имя файла на диске | `0482_запись2_Белый снег.mp3` |

## 4. Архитектура хранилища и ядра (IndexedDB v12)

1. **База данных:** `OfflineSongbookDB_v12`.
2. **Таблицы (ObjectStores):**
   - `songs` (keyPath: `id`) — реестр песен;
   - `audio` (keyPath: `id`) — метаданные дорожек;
   - `audioBlobs` (keyPath: `filename`) — **постоянное бинарное хранилище аудиофайлов MP3**;
   - `playlists` (keyPath: `id`) — плейлисты;
   - `playlistItems` (autoIncrement) — элементы плейлистов;
   - `settings` (keyPath: `key`) — настройки интерфейса и автопрокрутки;
   - `playerQueue` (keyPath: `id`) — сохранённая очередь плеера.
3. **Отказоустойчивое логирование:** `AppLogger` сохраняет последние 600 записей в `localStorage ('ov_persistent_debug_logs')`, предотвращая потерю отладочной информации при перезагрузке страницы.

## 5. Модуль конвертации DOCX, OpenSong и ChordPro (Data Studio)

Подсистема реализована нативно в `data/admin.html` и базируется на **геометрической привязке через метрики шрифта**:

### 5.1 Внутренняя каноническая модель песни
```typescript
interface Song {
  id: string;
  title: string;
  key?: string;
  capo?: string;
  lines: SongLine[];
}

interface SongLine {
  kind: 'verse' | 'chorus' | 'bridge' | 'instrumental' | 'blank';
  lyric: string; // Полная строка текста
  chords: Array<{
    name: string;       // Например: 'Am7/G'
    charIndex: number;  // Точный индекс символа в строке lyric
    confidence: number; // 0..1 (уверенность алгоритма)
    manual: boolean;    // Флаг ручной корректировки
  }>;
}
```

### 5.2 Алгоритм геометрического выравнивания (Dynamic Programming)
1. **Извлечение координат:** Нативный разбор XML-структуры DOCX (`w:p`, `w:r`, `w:b`, `w:tab`). Расчет горизонтальной координаты $X$ каждого аккорда и каждого символа текста через `measureText`.
2. **Точки привязки (Snap Points):**
   - Начало слов (штраф = 0);
   - Гласные звуки `[аеёиоуыэюя]` (штраф = $0.35 \times \text{em}$);
   - Согласные буквы (штраф = $1.2 \times \text{em}$);
   - Конец строки (штраф = $0.8 \times \text{em}$).
3. **Монотонное выравнивание:** Поиск глобального минимума функции стоимости через динамическое программирование с гарантией порядка следования аккордов.

### 5.3 Интерактивный редактор (Drag-and-Drop)
- DOM-режим: каждый символ текста обернут в отдельный элемент, аккорды позиционируются как плавающие чипы.
- Магнитное прилипание аккордов к слогам и началам слов при перетаскивании.
- Цветовой аудит качества распознавания:
  - 🟢 **Зеленый** (confidence > 0.8) — надежная привязка;
  - 🟡 **Желтый** (0.5–0.8) — требует внимания;
  - 🔴 **Красный** (< 0.5) — коллизия или спорная позиция.
- Быстрые горячие клавиши: `Tab`/`Shift+Tab` (навигация), `←`/`→` (посимвольный сдвиг), `Ctrl+←`/`→` (прыжок по слогам), `Enter` (правка названия), `Ins`/`Del` (добавление/удаление аккорда).

### 5.4 Экспорт и печать
- **OpenSong XML:** Формирование разметки с точечными аккордовыми строками (`.`) и отступами для защиты от наезда текста.
- **ChordPro:** Инлайн-вставка аккордов в скобках `[C]...`.
- **База `songs.csv`:** Прямой экспорт и объединение с рабочей базой песен.
- **Печать в PDF / DOCX:** Генерация чистых печатных листов для репетиций (режимы: с аккордами, только слова, двухколоночный песенник).

## 6. Пользовательский интерфейс и эргономика (UI/UX)

1. **Адаптивность под мобильные экраны (300px–500px):**
   - Применение `clamp()` для шрифтов и внутренних отступов;
   - Заголовок песни безопасно сжимается (`text-overflow: ellipsis`);
   - Блок метаданных (`key`, `capo`, кнопка `+`) зафиксирован (`flex-shrink: 0`) и гарантированно не обрезается на узких экранах.
2. **Плейлисты и списки:**
   - Системный список **«Подбор»** (`pl-temp`) навсегда закреплен на 1-м месте;
   - Иконный стиль действий (`↶`, `📥`, `+`), удаление дублирующих кнопок импорта из строк.
3. **Аудиоплеер и MediaSession:**
   - Пункт селектора источников **«Все записи»** активирован по умолчанию;
   - Экран блокировки и шторка смартфона отображают настоящее название песни из базы.

## 8. Архитектура v4.0.0: Capacitor + PWA Dual-Track Architecture

### 8.1 Целевые артефакты из единого ядра
1. **Нативное мобильное приложение (Capacitor Android/iOS):** сборка через `capacitor-app/www/` ➔ `npx cap sync`.
2. **PWA для десктопа и браузеров:** дистрибутив `dist/pwa/` с раздачей по Cache First (оболочка) и Network First (`manifest.json`).
3. **Локальный Wi-Fi сервер (`start_offline_server.py --serve-files`):** раздача полной медиатеки на репетиции без интернета.

### 8.2 Матрица хранения данных (Storage Matrix)
| Данные | Capacitor Native | PWA (Desktop/Web) | Local Server |
|---|---|---|---|
| **MP3 фонограммы** | `Directory.Data` (Android) / `Directory.Library` (iOS) | **OPFS (Origin Private File System)** | Прямые файлы `music/` |
| **Каталог (read-only)** | SQLite (`@capacitor-community/sqlite`) | IndexedDB | CSV напрямую |
| **Плейлисты и заметки** | SQLite | IndexedDB | IndexedDB |
| **Настройки** | `@capacitor/preferences` | `localStorage` | `localStorage` |

### 8.3 Инварианты безопасности и производительности
1. **Никаких MP3 в IndexedDB:** бинарные фонограммы сохраняются только в OPFS или нативной файловой системе.
2. **Никаких raw `file://` в `<audio src>`:** только `Capacitor.convertFileSrc()` или Blob URL из OPFS.
3. **Атомарные релизы:** синхронизация проверяет SHA-256 каждого трека. Битые файлы перекачиваются, устаревшие удаляются автоматическим Garbage Collector (GC).
