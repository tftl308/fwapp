# Исследовательские промты для архитектурного и алгоритмического анализа проекта «Огненный Ветер»

## 🧭 Промт №1: Кроссплатформенная архитектура с нулевым порогом входа (Zero-Effort UX)

```markdown
Ты — ведущий системный архитектор кроссплатформенных оффлайн-систем и эксперт по Web/PWA/Hybrid технологиям.

### Контекст:
Проект «Огненный Ветер» — это мобильный терминал музыканта (песенник с аккордами, плеер репетиционных/студийных фонограмм, сценический телесуфлёр с автопрокруткой).
Целевая аудитория — музыканты группы с разным уровнем технической грамотности. 
Используемые устройства:
- Смартфоны и планшеты Android (Xiaomi MIUI/HyperOS, Samsung OneUI и др.);
- iPhone и iPad (iOS Safari / WebKit);
- Ноутбуки и десктопы (Windows, macOS, Linux).

Ключевая проблема:
Музыканты часто репетируют и выступают в условиях полного отсутствия интернета (бункеры, подвалы, загородные площадки). При этом современные мобильные ОС (особенно Android 13/14 на Xiaomi и iOS) намертво блокируют работу с локальными файлами по протоколу `file:///` (null-origin sandbox, блокировка чтения аудио, сброс Blob-ссылок, невозможность создания ярлыка без системных диалогов).

### Задача исследования:
Разработать и обосновать техническую архитектуру распространения, установки и синхронизации данных продукта, которая:
1. Минимизирует действия конечного пользователя до правила «Один клик / сканирование QR-кода».
2. Работает бесшовно и единообразно на Android, iOS, Windows и macOS.
3. Позволяет музыканту оффлайн иметь доступ ко всей базе песен (700+ треков) и всей пачке аудиофайлов (250+ фонограмм в формате MP3).
4. Обеспечивает безболезненное обновление базы (песни и новые записи с репетиций), когда лидер группы выкладывает свежую версию каталога.

### Вопросы для детального анализа:
1. **Модель доставки приложения (Distribution Model):**
   - Сравнение вариантов:
     а) Единый локальный HTML-файл (текущий);
     б) PWA с хостингом на бесплатном CDN (GitHub Pages / Cloudflare Pages / Vercel) с Service Worker Cache API + Background Sync;
     в) Локальный Mesh/Wi-Fi сервер (ноутбук лидера раздаёт точку доступа без интернета);
     г) Упаковка в нативный легковесный APK / IPA через Capacitor / Tauri / WebExtension.
   - Какой подход даёт 100% оффлайн-гарантию и исключает блокировки Android/iOS?

2. **Хранение медиа-контента (Аудиофайлы 200–500 МБ):**
   - Где и как хранить сотни MP3 на клиенте без повторного скачивания:
     - Origin Private File System (OPFS);
     - IndexedDB Blob / ArrayBuffer storage;
     - File System Access API vs CacheStorage.
   - Какие лимиты дискового пространства накладывают iOS Safari и Android Chrome на оффлайн-хранилища?

3. **Синхронизация дельт (Delta Updates):**
   - Как реализовать обновление базы, чтобы музыкант не перекачивал гигабайты заново, а получал только изменившиеся аккорды или добавленные аудиозаписи?
   - Формат обмена: ZIP-пакет каталога, диффы CSV или бинарные бандлы SQLite/WASM?

4. **Итоговая рекомендация:**
   - Пошаговый сценарий «User Journey» для музыканта от момента получения ссылки до выступления на сцене.
```

## 🎼 Промт №2: Алгоритм геометрического выравнивания аккордов из DOCX/PDF в OpenSong и ChordPro с визуальным Drag-and-Drop редактором

```markdown
Ты — эксперт по компьютерной лингвистике, цифровой типографике, Computer Vision и музыкальным форматам нотации (OpenSong, ChordPro).

### Контекст:
Существует огромный исторический архив песен группы в формате `.docx` (Microsoft Word), набранный шрифтом **Times New Roman (пропорциональный / немоноширинный)**.
В оригинальных документах аккорды расположены отдельной строкой **над текстом**:
```text
C                Am
Белый снег заметёт пути...
```
Так как шрифт Times New Roman пропорционален (ширина буквы «м» и «w» в 3–4 раза больше ширины «i», «l» или пробела), простое количество пробелов в текстовом виде НЕ соответствует реальной горизонтальной позиции аккорда над слогом! При попытке открыть такой текст моноширинным шрифтом аккорды улетают на 5–15 символов в сторону.

### Цель задачи:
Разработать математический алгоритм и архитектуру веб-инструмента (SPA, работающего в браузере), который автоматически преобразует DOCX/PDF в канонический формат **OpenSong** (где аккордовая строка предваряется точкой `.C   Am`, а текстовая — пробелом ` Белый снег`), с последующим экспортом в **ChordPro** (`[C]Белый снег [Am]заметёт...`), дополненный интерактивным интерфейсом ручной доводки (Drag-and-Drop).

### Входные данные:
1. Исходный файл DOCX или экспортированный PDF.
2. Аккорды выделены **полужирным начертанием (Bold)** и состоят из латинских букв (A-G), знаков альтерации (#, b), цифр и приставок (m, sus, add, maj, 7, /bass).
3. Текст песен — на русском языке, обычным начертанием (Regular).

### Вопросы для детального анализа и проектирования:

1. **Математическая модель оптического выравнивания (Typography Physics):**
   - **Вариант А (Парсинг DOCX OpenXML):** Извлечение `w:r` (runs), анализ шрифта, кегля (`w:sz`), пробелов и горизонтального вычисления длины строки через таблицы ширин глифов шрифта Times New Roman (Kerning & Glyph Advance Widths).
   - **Вариант Б (Анализ PDF через PDF.js):** Использование точных геометрических координат `transform[4]` (X-координата) каждого глифа и текстового блока. Как построить матрицу проекции координаты `X_chord` на ближайший `X_char` в строке ниже?
   - **Вариант В (OCR / Визуальное сопоставление Bounding Box):** Рендеринг страницы в Canvas, поиск координат ограничивающих прямоугольников аккордов и проецирование центра/начала аккорда на слог текста.

2. **Эвристический алгоритм привязки аккорда к слогу (Chord-to-Syllable Snapping):**
   - В вокальной практике аккорд почти всегда падает на:
     а) Гласный звук ударного слога;
     б) Начало слова;
     в) Паузу между словами (если аккорд звучит на слабую долю/вступление).
   - Какую функцию стоимости (Cost Function) использовать для минимизации ошибки привязки?
     `Cost = |X_chord - X_syllable| + Penalty_NotVowel + Penalty_MiddleOfConsonants`

3. **Спецификация интерактивного редактора (Web Editor GUI):**
   - Предложи эргономику интерфейса:
     - Двухслойный холст: оригинальный вид песни;
     - Аккорды как перетаскиваемые «фишки» (chips/badges) над слогами;
     - Автоматическая расстановка магнитных точек привязки (Snap Points) на каждой гласной и начале каждого слова;
     - Горячие клавиши (стрелки влево/вправо для сдвига аккорда по слогам, Tab для перехода к следующему аккорду);
     - Режим предпросмотра результата в форматах OpenSong и ChordPro в реальном времени.

4. **Архитектура и стек реализации:**
   - Какие легковесные клиентские библиотеки без внешнего бекенда применить (docx.js, mammoth.js, pdfjs-dist, canvas)?
   - Предоставь псевдокод и ядро алгоритма проекции координат X_chord -> char_index.
```
