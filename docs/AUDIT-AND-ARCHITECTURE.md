# Архитектурное руководство и регламент аудита (System Architecture & Audit Guide)

Документ предназначен для проведения технического аудита кода, валидации решений по производительности, безопасности, UX и отказоустойчивости приложения **«Музыка Огненного Ветра»**.

---

## 1. Общие сведения и профиль назначения

- **Тип приложения:** Автономное Single-Page Application (SPA), поставляемое в виде единого самодостаточного HTML-файла (`огненныйветер.html` / `index.html`).
- **Среда выполнения:** Любой браузер стандарта ECMAScript 2020+ (Chrome 80+, Safari 14+, Firefox 78+, Edge 80+).
- **Сетевые требования:** 100% автономность. Полное отсутствие внешних запросов к CDN, шрифтам или сторонним API.
- **Протокол запуска:** Корректная работа через протокол `file://` (локальный запуск из файловой системы устройства) и `http://` / `https://` при размещении на веб-сервере.

---

## 2. Архитектурная карта компонентов

Приложение спроектировано по принципу слабой связанности (Loose Coupling) и строгой модульности:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        AppController (Фасад / UI)                      │
├─────────────────┬──────────────────────┬───────────────┬───────────────┤
│    Store        │  StorageRepository   │  SongParser   │ SearchEngine  │
│ (Иммутабельный  │ (IndexedDB +         │  & Transposer │ (Инвертир. +  │
│  State, PubSub) │  Fallback Storage)   │ (ChordPro, H) │  Триграммы)   │
├─────────────────┼──────────────────────┼───────────────┼───────────────┤
│  AudioPlayer    │  TaggedNotesHelper   │  UndoManager  │   Renderer    │
│ (MediaSession,  │ (Мультипрофильные    │ (История 30   │ (Безопасный   │
│  Плеер AIMP)    │  заметки команды)    │  снапшотов)   │  DOM-билдер)  │
└─────────────────┴──────────────────────┴───────────────┴───────────────┘
```

### Назначение ключевых модулей:

1. **`Store`**:
   - Централизованное реактивное состояние.
   - Метод `getState()` возвращает поверхностную копию (`Object.assign({}, this.state)`), предотвращая неконтролируемые внешние мутации.
   - Поддерживает раздельные идентификаторы `currentPlaylistId` (каталог) и `concertPlaylistId` (сцена).

2. **`StorageRepository`**:
   - Первичное хранилище — `IndexedDB` (база `OfflineSongbookDB_v10`).
   - Автоматический fallback на `localStorage` при блокировке IndexedDB (например, в приватном режиме Safari).
   - Точечное сохранение одиночных записей (`putOne`) исключает перезапись всей базы при обновлении одной заметки.
   - Защита от переполнения квоты (`QuotaExceededError`) с информированием пользователя через UI Toast.

3. **`SongParser & ChordTransposer`**:
   - Двунаправленный разбор ChordPro в связанные слоги-аккорды (`parseChordProToSyllables`).
   - Транспонирование с сохранением знаков альтерации (диезы не превращаются в бемоли и наоборот).
   - Транспонирование басовой ноты в слэш-аккордах (`A/C#` -> `H/D#`).
   - Поддержка переключения европейской (`H`/`B`) и американской (`B`/`Bb`) нотации.

4. **`SearchEngine`**:
   - Двухфазный индекс: инвертированный поиск по точным лексемам + триграммный поиск по расстоянию Дамерау — Левенштейна (порог опечаток ≤ 2).
   - Парсер встроенных фильтров: `тэг:`, `автор:`, `key:`.
   - Изолированный рендер результатов (`updateCatalogResultsOnly`) без пересоздания инпута поиска и потери фокуса ввода.

5. **`AudioPlayerService`**:
   - Воспроизведение треков сетлиста или конкретной песни.
   - Прогресс-бар обновляется через `requestAnimationFrame` и прямой DOM-манипулятор, исключая вызовы `setState` и блокировку UI.
   - Очередь `playerQueue` сохраняет только сериализуемые метаданные, не сохраняя временные Blob Object URLs в базу данных.
   - Кнопки управления блокируются (`disabled`), если в очереди нет треков.

6. **`TaggedNotesHelper`**:
   - Единое поле заметок для 6 профилей: `leader`, `piano`, `bayan`, `electric`, `bass`, `drums`.
   - Дедупликация: удаление блока `general`, если его текст полностью повторяет профильную заметку.
   - Устаревшие роли `vocal` и `acoustic` автоматически маппятся на `leader`.

## 3. Критерии безопасности и аудита

1. **Защита от XSS:**
   - Категорический отказ от конкатенации сырых строк через `innerHTML` для отображения пользовательских данных.
   - Использование безопасных методов `document.createElement`, `textContent` и `Renderer.renderHighlightedText`.

2. **Защита от CSV-инъекций:**
   - Экранирование управляющих символов и формул Excel (`=`, `+`, `-`, `@`) при экспорте данных.

3. **Соблюдение лимитов памяти:**
   - Контроль размера DOM-дерева через пагинацию («Показать ещё» по 60 песен).
   - Очистка таймеров автоскролла и отключение Screen Wake Lock при выходе из сценического режима.
