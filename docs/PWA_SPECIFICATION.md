# Спецификация PWA приложения «Огненный Ветер» (Архитектура, Пользователь и Админ)

Версия: 4.5.0 (PWA-First Architecture, GitHub Pages Deployment)
Дата обновления: 2026-10-14
Целевая платформа: Progressive Web App (PWA) / Мобильные и десктопные веб-браузеры (Chrome, Safari iOS, Firefox, Edge, Яндекс.Браузер).

---

## 1. Концепция и Архитектура Системы

Приложение «Огненный Ветер» ориентировано на полное автономное (offline-first) использование музыкальными командами, вокалистами и звукооператорами на репетициях и богослужениях.

### 1.1 Ключевые компоненты
1. **PWA Клиент (`index.html`)**:
   - Полнофункциональное SPA приложение с сервис-воркером (`sw.js`).
   - Автономная база данных в браузере на базе **IndexedDB** (`fwapp_db` / хранилища `songs`, `tags`, `songTags`, `playlists`, `playlistItems`, `audio`, `settings`, `audioBlobs`).
   - Встроенный каталог 700 песен (`INLINED_SONGS_CSV_DATA`) для мгновенного первого старта без задержек сети.
   - Поддержка фонограмм (MP3/WAV/M4A), встроенный плеер с извлечением ID3 APIC обложек альбомов.
   - Сценический (концертный) полноэкранный режим с автоподгонкой шрифта PT Serif.

2. **Data Studio / Кабинет Администратора (`data/admin.html`)**:
   - Автономный инструмент подготовки, валидации, разметки и экспорта базы песен.
   - Модули импорта DOCX, разметки секций `[V1]..[Vn]`, `[C]`, `[B]`, нормализации припевов/бриджей (`Пр.`, `Бр.`).
   - Редактор метаданных, тональностей, темпа, авторства, пользовательских заметок (user1..user3).
   - Генератор канонических CSV файлов (`data/songs.csv`, `data/audio.csv`, `data/tags.csv`).

3. **Легковесный автономный ридер (`огненныйветер.html` / `dist/reader/index.html`)**:
   - Монолитный HTML-файл без внешних зависимостей для мгновенного открытия на любых устройствах.

4. **Service Worker (`sw.js`) и обновление (`UpdateEngine`)**:
   - Стратегия: Network-First для манифеста релизов `data/version.json`.
   - Кэширование всех основных ассетов ядра (PWA Shell).
   - Прямой обход кэша для тяжёлых аудиофайлов (`music/*.mp3`).

## 2. Руководство Пользователя (PWA Client)

### 2.1 Каталог песен и Поиск
- **Умный поиск (SearchEngine)**:
  - **Любой порядок слов**: многословный запрос («белый снег» / «снег белый») находит песни независимо от порядка слов в названии или тексте.
  - **Приоритет точного совпадения**: точные совпадения слов в тексте песни без опечаток (`exactBodyCount * 10000`) ранжируются строго выше, чем нечёткие совпадения с опечатками в названии (`fuzzyTitleCount * 2000`).
  - **Поиск по номеру**: ввод 4-значного или короткого номера (например `482` или `#0482`) моментально находит нужную песню.
  - **Фильтры**: поддержка синтаксиса `тэг:праздник`, `автор:имя`, `тон:Am`.

### 2.2 Просмотр песни
- **Аккорды и слоги**: отображение надстрочных аккордов с единым шрифтом PT Serif (нормальный текст 400, полужирные аккорды 700).
- **Транспонирование**: кнопки `-1` / `+1` с поддержкой европейской (B/Bb) и немецкой (H/B) нотаций.
- **Индивидуальный Pinch-to-Zoom**: масштабирование щипком двумя пальцами применяется **исключительно к блоку текста и аккордов (`#lyrics-box`)**, не ломая шапку страницы, кнопки действий и поле заметок.
- **Заметки музыканта**: переключение ролей (Лидер, Акустика, Клавиши, Бас, Ударные и др.), сохранение персональных заметок и меток user1..user3.
- **Аудиодорожки**: внизу карточки песни выводятся привязанные фонограммы (студия, репетиция, минус, live). Нажатие запускает воспроизведение.

### 2.3 Студийный плеер
- Воспроизведение дорожек из памяти RAM, локального хранилища IndexedDB или папки `music/`.
- Автоматическое извлечение встроенных обложек альбомов ID3v2 APIC.
- Обложка отображается стабильно как в мини-плеере (docked bar), так и на экране студийного плеера при любых переходах.
- Поддержка списков воспроизведения и управления очередью.

### 2.4 Концертный режим (Режим Сцены)
- Вход через иконку микрофона `🎤` (для одиночной песни или сетлиста).
- **PT Serif Character-Level Metrics**:
  - Приложение предпросчитывает размер шрифта для каждой песни под ширину и высоту экрана текущего устройства.
  - Самая длинная строка гарантированно умещается без нежелательного переноса.
  - Компактные песни заполняют экран по высоте, исключая прокрутку.
- **Персональная память устройства**:
  - Пользователь может изменить размер шрифта (кнопками `A-` / `A+` или pinch-zoom двумя пальцами).
  - Настройка сохраняется в `localStorage` для данной песни на данном устройстве и действует во всех списках.
- **Автопрокрутка**: плавный скроллинг с регулируемой скоростью для длинных произведений.

## 3. Руководство Администратора (Data Studio)

### 3.1 Работа с DOCX и текстами песен
1. Открыть `data/admin.html` в браузере.
2. Вкладка **«Импорт / Конвертер DOCX»**:
   - Перетащить файл сборника DOCX.
   - Алгоритм автоматически определяет маркеры куплетов `1.`/`2.`/`[V1]`, припевов `Пр.`/`[C]` и бриджей `Бр.`/`[B]`.
   - Строгое правило: слова вроде «Правда» или «Братья» не распознаются как секции, требуется точка (`Пр.`, `Бр.`).
   - Связки через дефис (например `Dm-E`) автоматически разделяются на независимые аккорды (`Dm E`).

### 3.2 Редактор базы данных песен
- Поиск и фильтрация песен по названию, автору, тональности, номеру.
- Редактирование ChordPro разметки, метаданных и секции презентации OpenSong.
- Экспорт обновлённого `songs.csv` (разделитель `;`, кодировка UTF-8).

### 3.3 Привязка фонограмм
- Именование файлов фонограмм: `{ID}_{ТИП}_{НАЗВАНИЕ}.mp3` (например `0482_studio_Белый_снег.mp3`).
- Таблица соответствий экспортируется в `data/audio.csv`.

## 4. Архитектура Обработки Событий (Event Lifecycle Rules)

Приложение построено на декларативной модели делегирования событий без утечек памяти:

```
[Пользовательский жест / Клик]
         │
         ▼
[document.addEventListener delegated dispatcher]
         │
         ├── e.target.closest('[data-action]')
         │       ├── 'open-song'                 ──> store.setState({ currentSongId }) ──> renderSongDetailView
         │       ├── 'transpose-plus / minus'    ──> currentSongTranspose +/- ──> renderLyrics
         │       ├── 'open-concert-single-song'  ──> openConcertSingleSong ──> fitConcertSongToViewport
         │       ├── 'concert-font-plus / minus' ──> localStorage('ov_concert_font_<songId>') ──> style.setProperty
         │       ├── 'play-song-variant'         ──> audioPlayer.playIsolatedTrack ──> extractCoverFromBlob
         │       └── 'switch-tab'                ──> store.setState({ currentTab }) ──> renderCurrentView
         │
         ├── touchstart / touchmove (Pinch-to-zoom)
         │       ├── Song Detail: scale ONLY #lyrics-box via CSS transform (Origin: top left)
         │       └── Concert Mode: scale --font-concert with instant localStorage persistence per song
         │
         └── PopState / History Navigation
                 └── Back navigation cleanly resets zoom and restores catalog scroll position
```

### 4.1 Правила обработки событий:
1. **Делегирование (Delegated Click)**:
   - Все интерактивные элементы размечаются атрибутом `data-action="..."`.
   - Клики внутри полей формы (`<input>`, `<textarea>`, `<select>`) изолируются через `stopPropagation`, предотвращая сброс фокуса клавиатуры и случайные переходы.

2. **Защита жестов (Touch Gesture Isolation)**:
   - События `touchstart` внутри полей ввода заметок (`#input-profile-note`, `user1..3`) изолированы от обработки свайпов и pinch-to-zoom.
   - Масштабирование щипком в карточке песни строго ограничено элементом `#lyrics-box`.

3. **Синхронизация состояния плеера**:
   - Запуск трека генерирует событие `play`, активирующее фоновый MediaSession API с метаданными песни и обложкой.
   - При смене вкладок мини-плеер скрывается на экране студийного плеера (`currentTab === 'player'`) и восстанавливается в остальных вкладках.
