# Спецификация и план модернизации DOCX-парсера, Drag-and-Drop редактора и генератора форматов в Data Studio (admin.html)

---

## 1. Концепция и проблематика

Исторический каталог песен создавался в Microsoft Word (`.docx`) с использованием **пропорционального шрифта Times New Roman**.
В исходных документах аккорды расположены отдельной строкой над текстом:
```text
C                Am
Белый снег заметёт пути...
```
В пропорциональных шрифтах глифы имеют разную ширину (например, ширина «W» или «М» в 3–4 раза превышает ширину «i», «l» или пробела). По этой причине:
1. **Подсчёт пробелов не работает:** позиция аккорда по количеству пробелов в тексте приводит к систематическому смещению на 5–15 символов при отображении в моноширинном виде или конвертации в ChordPro/OpenSong.
2. **Наивный парсинг разрушает форматирование:** парсеры общего назначения (например, `mammoth.js`) склеивают текстовые раны (`w:r`) и теряют информацию о полужирном начертании (`w:b`), размерах шрифта (`w:sz`) и табуляциях (`w:tab`).

## 3. Единая модель данных (Canonical Song Model)

```typescript
interface Song {
  id: string;              // 4-значный ID ('0482')
  number: string;          // Номер в сборнике ('482')
  title: string;           // Название ('Белый снег')
  alt_title?: string;
  author?: string;
  key?: string;            // 'Am'
  capo?: string;           // '2'
  tempo?: string;          // '90'
  time_signature?: string; // '4/4'
  lines: SongLine[];
  notes?: string;
}

interface SongLine {
  kind: 'verse' | 'chorus' | 'bridge' | 'instrumental' | 'blank';
  lyric: string;           // Полная строка текста (Intl.Segmenter графема)
  chords: Array<{
    name: string;          // Название аккорда ('Am7/G', 'H7')
    charIndex: number;     // СТРОГАЯ привязка к индексу графемы в lyric
    confidence: number;    // Оценка совпадения 0..1
    manual: boolean;       // Флаг ручной корректировки пользователем
  }>;
}
```

## 4. Алгоритмические спецификации

### 4.1 Извлечение геометрии из DOCX (`extractDocx`)
- Парсинг `word/document.xml` через нативный браузерный `DOMParser`.
- Чтение стилей `word/styles.xml` для разрешения неявного полужирного начертания в `w:pPr/w:pStyle`.
- Расчет ширины и положения фрагментов текста через `OffscreenCanvas.measureText` с предзагруженным локальным шрифтом Times New Roman.
- Регулярное выражение для распознавания аккордов (с поддержкой европейской традиции H/B):
  ```javascript
  const CHORD_RE = /^[A-H](#|b)?(m|maj|min|dim|aug|sus|add)?\d{0,2}(sus\d|add\d{1,2})?(\/[A-H](#|b)?)?$/;
  ```

### 4.2 Монотонное выравнивание Dynamic Programming (`alignChords`)
- Для строки текста строится массив точек привязки `SnapPoint`:
  - Начало слов: `cost_penalty = 0`;
  - Гласные звуки `[аеёиоуыэюяaeiouy]`: `cost_penalty = 0.35 * em`;
  - Согласные буквы: `cost_penalty = 1.2 * em`;
  - Конец строки (для отыгрышей): `cost_penalty = 0.8 * em`.
- Матрица DP обеспечивает строгое сохранение порядка аккордов слева направо без коллизий в одном символе:
  $$\text{dp}[k][i] = \text{cost}(k, i) + \min_{j < i} \text{dp}[k-1][j]$$

### 4.3 Преобразование в форматы

#### Экспорт в ChordPro:
Аккорды вставляются в строку текста, начиная с конца (в порядке убывания `charIndex`), чтобы не сбивать смещения последующих символов:
```text
[Am]Белый снег за[Dm]метёт пути...
```

#### Экспорт в OpenSong:
Аккордовая строка формируется с префиксом точки (`.`), а текстовая — с ведущим пробелом (` `). При формировании аккордовой строки учитывается минимальный интервал между аккордами во избежание слипания:
$$\text{col} = \max(\text{chord.charIndex}, \text{line.length} + 1)$$
Пример:
```text
.Am            Dm
 Белый снег заметёт пути...
```

#### Экспорт в CSV (`data/songs.csv`):
Результат конвертации бесшовно интегрируется в общую базу данных приложения `songs.csv` с сохранением полей `body_chordpro` и `body_plain`.

## 5. Интерактивный Drag-and-Drop редактор

- **DOM-архитектура:** Текст песни выводится как последовательность `<span class="char-cell" data-idx="i">`, гарантируя 100% совпадение с системными шрифтовыми метриками.
- **Интерактивные аккордовые фишки (Chips):**
  - Подсвечиваются цветовым индикатором уверенности (зеленый / желтый / красный);
  - Перетаскиваются мышью или тачем вдоль строки с магнитной подсветкой слогов;
  - Поддерживают вертикальный перенос между строками при исправлении ошибок деления на куплеты;
  - Позволяют редактирование названия кликом (Enter) с мгновенной валидацией.
- **Горячие клавиши:**
  - `Tab` / `Shift+Tab` — переход к следующему/предыдущему аккорду;
  - `←` / `→` — сдвиг позиции на 1 символ;
  - `Ctrl + ←` / `Ctrl + →` — прыжок на следующий слог / начало слова;
  - `Insert` / `Delete` — добавление нового аккорда над текущим символом или удаление;
  - `Ctrl + Z` / `Ctrl + Y` — отмена и возврат действий.

## 6. Печать и тиражирование (PDF & DOCX)

1. **Печать PDF (через `pdf-lib`):**
   - Формат страницы A4, поля 15 мм;
   - Заголовок, тональность, каподастр, темп;
   - Варианты: с аккордами над текстом, сетка для аккомпанемента, чистый текст для вокалистов.
2. **Печать / Экспорт DOCX (через `docx` library):**
   - Генерация чистого DOCX-файла для распространения музыкантам.
3. **Пакетный режим (Batch Conversion):**
   - Загрузка пачки DOCX-файлов;
   - Пакетная конвертация в OpenSong / ChordPro / CSV;
   - Скачивание единого ZIP-архива с файлами песен и отчетом качества `audit_report.csv`.
