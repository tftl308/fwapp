# Стратегия идентификации песен, импорта PDF и именования MP3-аудиофайлов

---

## 1. Концепция хронологического ID (Номер выхода песни)

### Анализ предоставленных материалов
1. В документе **«Алфавитный список.pdf»** зафиксирован канонический реестр из **687 песен** служения «Огненный ветер».
2. Каждой песне сопоставлен порядковый номер её создания/выхода (хронологический ID от `001` до `687+`).
3. Так как тексты рождаются раньше аккордовых сеток и выходят не в алфавитном порядке, сквозной номер выхода является идеальным **первичным неизменяемым ключом (Primary Key)**.
4. При выходе сборников (например, сборник **«Огненный ветер (21).pdf»**) номер песни в конкретной брошюре (`1..21`) является лишь номером страницы/позиции в этой подборке, в то время как её глобальный внутренний ID берется из общего хронологического реестра:
   - *«Белый снег»* → Позиция в сборнике 21: `1`, **Глобальный ID:** `482`.
   - *«Берег правый»* → Позиция в сборнике 21: `2`, **Глобальный ID:** `507`.
   - *«Благодарим за всё Тебя»* → Позиция в сборнике 21: `3`, **Глобальный ID:** `566`.
   - *«Бога я в тесноте призвал»* → Позиция в сборнике 21: `4`, **Глобальный ID:** `375`.
   - *«Божий ветер»* → Позиция в сборнике 21: `5`, **Глобальный ID:** `538`.
   - *«Если тебя не любят»* → Позиция в сборнике 21: `6`, **Глобальный ID:** `466`.

### Стандарт формата ID
- Строковый стабильный ключ: `ID-001`, `ID-042`, `ID-482`, `ID-687`.
- Числовое поле сортировки: `number: 482`.

## 2. Стратегия классификации и именования файлов MP3

Для автоматической привязки файлов из папки `music/` к карточкам песен без ручного сопоставления утверждается четкий шаблон именования:

### Формула имени файла
```text
{ID}_{TYPE}_{TITLE}.mp3
```

Где:
- `{ID}` — трёхзначный (или 4-значный) хронологический номер выхода песни (`001`, `042`, `482`).
- `{TYPE}` — код категории записи (один из 6 стандартизированных типов):
  - `studio` (или `orig`) — **Студийный релиз** (мастеринг, чистовой трек)
  - `live1` — **Живая запись 1** (служение / воскресное собрание)
  - `live2` — **Живая запись 2** (фестиваль / конференция)
  - `rehearsal` (или `reh`) — **Репетиция** (черновой рабочий прогон с комментариями)
  - `acoustic` (или `acoust`) — **Акустика** (гитара + голос или фортепиано + голос)
  - `vocal` (или `voice`) — **Голос / а капелла** (голосовая партия для разучивания)
  - `minus` — **Фонограмма / минус** (для сольного или хорового пения)
- `{TITLE}` — понятное название песни латиницей или кириллицей.

### Примеры имен файлов
```text
music/482_studio_Belyj_sneg.mp3
music/482_live1_Belyj_sneg_sluzhenie.mp3
music/482_acoustic_Belyj_sneg_piano.mp3
music/482_vocal_Belyj_sneg_golos_partiya.mp3
music/507_studio_Bereg_pravyj.mp3
music/507_rehearsal_Bereg_pravyj.mp3
music/538_live1_Bozhij_veter.mp3
```

### Как это обрабатывает приложение
1. При сканировании папки или перетаскивании MP3 парсер считывает префикс регулярным выражением:
   `^(\d+)_([a-zA-Z0-9]+)_(.*)\.(mp3|wav|ogg|m4a)$`
2. Находит песню с соответствующим `ID` (например, `482`).
3. Автоматически создает запись в аудио-каталоге песни с правильным типом (`original`, `live`, `rehearsal`, `demo`, `minus`).
4. Если у файла заполнены ID3-теги (название трека, исполнитель, год), плеер подхватывает их для показа на экране блокировки смартфона через Media Session API.

## 3. Архитектура парсера PDF/DOCX для аккордовых сеток

В документе «Огненный ветер (21).pdf» аккорды расположены классическим способом: над строкой текста с пробельным позиционированием над ударным слогом.

Парсер преобразует такие страницы в канонический формат ChordPro:
1. Вычисление горизонтальной координаты $X$ каждого аккорда относительно ширины глифов текста.
2. Вставка аккорда в квадратных скобках `[Am]` перед соответствующей буквой текста.
3. Распознавание соединенных дефисом гармонических групп: `[Dm-E]`, `[Dm-G]`.
4. Сохранение знака переноса тональности: например, `(+1)`, `(+2)`, `(+4)` в заголовке песни трансформируется в базовую тональность с учетом оригинальной тональности куплетов.
