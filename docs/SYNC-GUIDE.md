# Руководство по синхронизации и режимам работы (SYNC-GUIDE)

В этом документе честно и подробно описано, как устроена работа с данными в браузере при открытии через `file://` и по сети.

---

## 1. Честная матрица возможностей браузера

| Функция | Режим `file://` (двойной клик) | Локальный сервер `http://localhost` | Защищенный `https://` |
|---|---|---|---|
| Хранение в базе IndexedDB | **ДА** (Chrome, Firefox, Edge, Android) / Fallback в localStorage | **ДА** | **ДА** |
| Воспроизведение локальных треков | **ДА** (через выбор папки или диалог файлов) | **ДА** | **ДА** |
| Экспорт и импорт ZIP/CSV | **ДА** (100% офлайн через браузерный Blob) | **ДА** | **ДА** |
| Сверка контрольных сумм SHA-256 | **ДА** (через встроенный Web Crypto API) | **ДА** | **ДА** |
| PWA (установка как приложение) | **НЕТ** (браузеры требуют HTTPS) | **НЕТ** (требует HTTPS) | **ДА** |
| Service Worker (фоновый кэш) | **НЕТ** (запрещен спецификацией W3C для `file://`) | **ДА** (только на localhost) | **ДА** |
| Скачивание по протоколу FTP | **НЕТ** (поддержка FTP удалена из всех браузеров с 2021 г.) | **НЕТ** | **НЕТ** |
| Прямая фоновая запись на диск без клика | **НЕТ** (политика безопасности песочницы браузера) | **НЕТ** | **НЕТ** |

---

## 2. Основной режим: Локальный пакет обновления (Режим A)

Это самый надежный сценарий работы для музыкантов и администратора базы:

1. Администратор редактирует таблицы и формирует ZIP-архив с обновлением (или экспортирует его прямо из приложения одной кнопкой «Экспорт резервной копии / ZIP»).
2. В архиве содержатся таблицы CSV и `manifest.json` со списком контрольных сумм SHA-256.
3. Музыкант открывает `index.html`, переходит в раздел **«Настройки» → «Импорт / Синхронизация»** и выбирает скачанный ZIP-файл.
4. Приложение:
   - распаковывает архив силами встроенного легковесного декомпрессора;
   - проверяет совпадение контрольных сумм SHA-256 через `crypto.subtle.digest`;
   - выполняет предварительный просмотр изменений: сколько песен добавлено, сколько обновлено, есть ли конфликты;
   - обновляет только измененные записи, не создавая дубликатов;
   - сохраняет пользовательские заметки и настройки плейлистов.

## 3. Сетевой режим: Публичный HTTPS-манифест (Режим B)

Если у вашей группы есть веб-сервер, GitHub Pages или корпоративное облако:

1. Разместите манифест и CSV-файлы по защищенному адресу `https://your-domain.com/songs/manifest.json`.
2. **Критически важное требование CORS**:
   Сервер обязан отдавать HTTP-заголовок `Access-Control-Allow-Origin: *` (или разрешать `Origin: null`, который передается браузером при запросах из `file://`).
3. Музыкант вводит адрес манифеста в настройках и нажимает кнопку **«Проверить обновления»**.
4. Приложение загружает манифест, сравнивает хэши SHA-256 с локальными записями и подгружает только те таблицы, которые реально изменились.
5. При отсутствии интернета или если сервер не настроил CORS, приложение вежливо сообщит:
   *«Сетевое обновление недоступно из-за политики безопасности сервера (CORS). Воспользуйтесь ручным импортом ZIP-пакета».*

## 4. Работа с аудиозаписями

Браузерная песочница не позволяет веб-странице сканировать произвольные жесткие диски компьютера в фоновом режиме. Поэтому для музыки предусмотрены три комфортных пути:

1. **Относительный путь рядом со сборником**:
   Если папка `music/` лежит рядом с `index.html`, файлы подхватываются естественным путем.
2. **Кнопка «Выбрать папку с треками» (File System Access / Directory Picker)**:
   Один раз указываете папку на устройстве, и плеер мгновенно связывает треки с записями в базе по именам файлов.
3. **Прямой выбор файла через кнопку обзора**:
   Создается временный безопасный `Blob URL`, не расходующий дисковую квоту браузера.
