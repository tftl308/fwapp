# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ И АРХИТЕКТУРА ПРОЕКТА «ОГНЕННЫЙ ВЕТЕР» (PWA + Light Reader)
**Версия документа:** 4.3.0-20261005  
**Статус:** Каноническая спецификация для полного аудита кода сторонними ИИ-моделями (Claude, GPT, DeepSeek, Gemini, Qwen).

---

## 1. Назначение и Архитектурный Стек
Проект **«Музыка Огненного Ветра»** — это отказоустойчивое PWA и карманный автономный сборник для музыкантов, вокалистов и звукорежиссёров, объединяющий:
1. **Канонический каталог на 700 песен** (номера `0001`–`0700`, тональности, каподастры, темп, тактовый размер, тексты, разметка ChordPro, музыкантские заметки).
2. **Студийный аудиоплеер** (поддержка локальных MP3 с распознаванием маски `ID_TYPE_TITLE`, чтение вшитых ID3 APIC обложек альбомов).
3. **Концертный режим (режим сцены)**:
   - Высококонтрастные сценические темы оформления: `paper` (светлая бумага, максимально близкая к белому `#ffffff`), `amber` (янтарная на чёрном `#000000`), `dark` (тёмно-серая сцена).
   - Автоподгонка под высоту и ширину экрана смартфона (`fitConcertSongToViewport`).
   - Полный вывод текста всех куплетов и припевов без обрезания.
   - Компактный вывод строк без аккордов (без лишних вертикальных зазоров).
   - Жирные аккорды (`Golos Text`, 800–900 + subpixel shadow).
   - Транспонирование на лету (+/- полутона) с кнопкой быстрого сброса `+0`.
   - Регулировка межстрочного интервала («Плотнее» / «Шире»).
   - Автоскролл с педальным и клавиатурным управлением (PageDown/PageUp/Space/Escape).
   - Блокировка отключения экрана через `Screen Wake Lock API`.
4. **Интерактивные аппликатуры гитарных аккордов**:
   - Векторный SVG генератор с расширенной библиотекой на 92+ типов аккордов (мажор, минор, септаккорды, maj7, sus4, sus2, dim, aug, m7b5, add9, альтерированные и слэш-аккорды типа `D/F#`, `A/C#`, `G/B`).
   - Переключение между несколькими вариантами аппликатуры (I лад, баррэ III, V, VII, VIII лад).
   - Защита от случайных нажатий: показ диаграмм аккордов активен в основном режиме чтения и строго отключён в концертном режиме.
5. **Музыкантские заметки и профили**:
   - Профили: Лидер (вокал/акустика), Пианино, Баян, Соло-гитара, Бас-гитара, Барабаны.
   - Хранение под тэгами `[leader]`, `[piano]`, `[bayan]`, `[electric]`, `[bass]`, `[drums]` в поле `notes`.
   - Поддержка пользовательских меток и комментариев `user1`, `user2`, `user3`.
6. **Офлайн-первичность и PWA**:
   - 100% автономная работа после первой синхронизации.
   - Независимый Service Worker (`sw.js`) с кэшированием ядра и сетевым обходом для аудио.
   - Однокнопочное обновление каталога с GitHub Pages (`tftl308.github.io`) с защитой от затирания списков и заметок.

## 2. Структура Данных: Канонический CSV (22 поля)
Файл `data/songs.csv` содержит ровно 22 колонки с разделителем `;`:
```
id;number;title;author;key;capo;tempo;time_signature;duration;predelay;presentation;theme;alttheme;user1;user2;user3;lyrics;chordpro;notes;link_audio;link_youtube;custom_chords
```

### Спецификация полей:
* `id` — 4-значный строковый номер (`0001`–`0700`), первичный ключ.
* `number` — Номер песни в печатном сборнике.
* `title` — Каноническое название песни.
* `author` — Автор слов / музыки / перевода.
* `key` / `capo` — Основная тональность (например, `Em`, `G`, `A`) и положение каподастра (`+2`, `+3`).
* `tempo` / `time_signature` — Темп (BPM) и размер (`4/4`, `3/4`, `6/8`).
* `duration` / `predelay` — Длительность звучания и предзадержка (в секундах).
* `presentation` — Порядок куплетов для слайдов проектора (например, `1,C,2,C,B,C`).
* `theme` / `alttheme` — Основная и вспомогательная тематические категории.
* `user1`, `user2`, `user3` — Пользовательские метки (тональности исполнителя, статус разучивания, плейлисты).
* `lyrics` — Чистый текст песни для быстрого полнотекстового индексирования и поиска.
* `chordpro` — Текст с аккордами в квадратных скобках (стандарт ChordPro): `[Em]Берег [C]правый реки [G]большой`.
* `notes` — Заметки с тегами ролей: `[leader] Вступление с припева [piano] Арпеджио [drums] Сбивка на 4 такт`.
* `link_audio` / `link_youtube` — Ссылки на эталонные аудио- и видеозаписи.
* `custom_chords` — Пользовательские переопределения аппликатур или последовательностей.

## 3. Архитектура Хранилища (Storage Engine)
В браузере используется IndexedDB (`OfflineSongbookDB_v12`) со следующими объектными хранилищами:
1. `songs` (keyPath: `id`) — 700 песен каталога со всеми 22 полями.
2. `playlists` (keyPath: `id`) — Списки и сетлисты богослужений.
   * Системный список `pl-temp` («Подбор») защищён от удаления, создается автоматически при инициализации и гарантированно не затирается при обновлении с сервера.
3. `playlistItems` (keyPath: `id` / autoIncrement) — Состав песен в списках с полями `playlist_id`, `song_id`, `order`, `transpose`, `capo_override`, `note`.
4. `audio` (keyPath: `id`) — Метаданные фонограмм (без хранения тяжелого бинарного MP3 в JSON).
5. `audioBlobs` (keyPath: `filename`) — Локальное бинарное хранилище выбранных пользователем MP3 файлов для постоянного воспроизведения офлайн.
6. `settings` (keyPath: `key`) — Тема оформления, нотация (`H` / `B`), версия схемы.

## 4. Поисковый движок и Алгоритм Релевантности
Поиск в `SearchEngine.search(query)` реализован по 4-уровневой шкале очков:
1. **Tier 1:** Максимальное совпадение слов запроса в названии (`titleMatchesCount * 10000`).
2. **Tier 2:** Максимальное совпадение слов запроса в тексте (`bodyMatchesCount * 1000`).
3. **Tier 3:** Наличие хотя бы одного слова в названии.
4. **Tier 4:** Наличие хотя бы одного слова в тексте.
* Поддерживается нечёткий поиск (расстояние Дамерау-Левенштейна до 2 опечаток) и поиск по согласным сокращениям (подпоследовательности).
* В интерфейсе совпавшие слова и сокращения подсвечиваются тегом `<mark class="highlight">`.

## 5. Типографика и Цветовые Темы
* **Текст песен:** `Golos UI` / `Golos Text` (Medium, weight 500).
* **Аккорды над текстом:** `Golos Text` (Extra-Bold, weight 800-900 + text-shadow).
* **Интерфейс:** `Golos Text` / `Golos UI` (Bold, weight 700).
* **Тема Paper (Бумага):**
  * Фон приложения: чистый белый `#ffffff`, подложка `#fdfdfc`, карточки `#ffffff` / `#faf9f6`, границы `#f1ede6`.
  * Акцентные кирпично-пламенные аккорды `#d03000` / `#c03000`.

## 6. Механизм Обновлений (UpdateEngine) и Сохранение Данных
1. Клиент проверяет `data/version.json?_t={now}`.
2. Сверяются хэши `songs_hash`, `playlists_hash`, `notes_hash`.
3. При обновлении:
   * Каталог `songs.csv` обновляется в IndexedDB.
   * Системный список `pl-temp` («Подбор») и все пользовательские плейлисты (`pl-*`) **автоматически сохраняются и объединяются** (merge, а не drop).
   * Заметки музыкантов и пользовательские поля `user1`–`user3` бережно сохраняются.
   * Метод `addSongToPlaylist` имеет fallback-защиту: при отсутствии `pl-temp` в базе он моментально регистрируется и сохраняется, гарантируя безотказное добавление песен в список.
   * Кэш браузера и Service Worker инвалидируются для мгновенного применения новой сборки.
